# v0.4 Incremental Maintenance Workflow

Date: 2026-05-30

Status: closure-candidate workflow baseline.

## Position

v0.4 is the incremental maintenance layer after v0.21 routing and v0.3 graph
construction/query. It is not a generic JSONL CRUD layer. Its job is:

```text
new / changed evidence
  -> create bounded incremental candidates
  -> route human review where needed
  -> publish current views
  -> mark dependent query / graph / visual assets stale
  -> refresh affected audit views
```

The first closed workflow is intentionally conservative:

- S0B/S1/S2 history remains append-only.
- Human review gates apply/publish effects.
- Current views are derived projections, not canonical truth rewrites.
- Graph remains candidate/projection material.
- Visualization is audit support only.

## Executable Full Review Package

The full workflow package includes the human-review step. It is the preferred
closure smoke for v0.4.

Prepare a fresh package:

```bash
python -m tools.maintenance.v04_full_review_workflow_package_runner prepare \
  --workspace users/_v04_full_review_workflow_manual \
  --reset \
  --port 8765
```

Then start the review WebUI using the command written in:

```text
maintenance_v04_full_review_workflow/HUMAN_REVIEW_INSTRUCTIONS.md
```

The reviewer must inspect and submit the review session. The package is not
allowed to finalize until these files exist:

```text
human_review/review_decisions.jsonl
human_review/review_session_manifest.json
```

After review submission:

```bash
python -m tools.maintenance.v04_full_review_workflow_package_runner finalize \
  --workspace users/_v04_full_review_workflow_manual
```

The finalize stage runs:

```text
review_decisions + review_session_manifest
  -> incremental_review_decision_applier
  -> S1 latest view after review
  -> S1 current publish
  -> S2 current publish
  -> graph candidate latest-view
  -> graph current publish
  -> dependency map / query invalidation
  -> affected visual review refresh
```

Tests may use `--auto-review-for-test`; normal manual packages should not.

## Post-Review Smoke Package

There is also a lower-level post-review smoke package:

```text
tools/maintenance/v04_incremental_workflow_smoke_runner.py
```

It starts after review artifacts are already represented as overlay/decision
inputs. It is useful for fast runner orchestration checks, but it is not the
full human-review workflow.

Default command:

```bash
python -m tools.maintenance.v04_incremental_workflow_smoke_runner \
  --workspace users/_v04_incremental_workflow_smoke_manual \
  --reset
```

The smoke package writes:

```text
maintenance_v04_workflow_smoke/
  inputs/
  s1_after_review/
  s1_current/
  s2_current/
  graph_latest_base/
  graph_latest_after_increment/
  graph_current/
  graph_v031_visual_review_incremental/
  v04_incremental_workflow_smoke_manifest.json
  v04_incremental_workflow_smoke_report.md
```

It uses synthetic rows and does not call a live provider.

## Workflow Steps

### 1. S1 Review Overlay To S1 Current

Input:

```text
s1_active_before_review.jsonl
s1_incremental_candidates.jsonl
s1_latest_view_overlay.jsonl
```

Runner:

```text
tools/maintenance/s1_review_overlay_consumer.py
```

Output:

```text
s1_latest_view_after_review.jsonl
s1_latest_view_after_review_excluded.jsonl
```

Then publish:

```text
tools/maintenance/s1_current_view_publisher.py
```

Output:

```text
s1_current/s1_current.jsonl
s1_current/s1_current_excluded.jsonl
s1_current/s1_status_transitions.jsonl
maintenance/latest_views/s1_latest_view.jsonl
```

Meaning:

Reviewed S1 candidates become the machine-consumed current S1 view. Old S1
rows are tagged historical/stale/excluded instead of silently disappearing.

### 2. S2 Review Decisions To S2 Current

Input:

```text
s2_base_reviewed_units.jsonl
s2_incremental_candidates.jsonl
s2_review_decisions.jsonl
s2_affected_units.jsonl
```

Runner:

```text
tools/maintenance/s2_current_view_publisher.py
```

Output:

```text
s2_current/s2_current.jsonl
s2_current/s2_current_excluded.jsonl
s2_current/s2_status_transitions.jsonl
maintenance/latest_views/s2_latest_view.jsonl
```

Meaning:

Reviewed S2 candidates become the current portrait/query projection. Old S2
units directly affected by the accepted increment are tagged historical/stale.
Canonical `portrait/reviewed_units.jsonl` is not rewritten.

### 3. Graph Candidate Latest View

Input:

```text
base graph candidate tables
incremental graph candidate tables
```

Runner:

```text
tools/maintenance/graph_candidate_latest_view_runner.py
```

Output:

```text
graph_nodes_latest_view.jsonl
graph_edges_latest_view.jsonl
graph_claims_latest_view.jsonl
evidence_links_latest_view.jsonl
*_excluded.jsonl
latest_views/
```

Meaning:

Incremental candidate graph rows overlay base rows by object id. Low-value or
review-required graph rows are excluded from the active current projection.
This is still not graph truth.

### 4. Graph Current Publish

Input:

```text
graph candidate latest-view bundle
```

Runner:

```text
tools/maintenance/graph_current_view_publisher.py
```

Output:

```text
graph_current/
maintenance/published_views/
```

The publisher automatically runs:

```text
graph_dependency_map_builder
  -> graph_query_index_invalidation_runner
  -> graph_visual_review_incremental_refresher
```

Meaning:

Query consumers can discover `graph_current/` by default, while dependency,
invalidation, and visualization artifacts describe what changed and what should
be refreshed. Query indexes are not silently rebuilt.

### 5. Incremental Visual Review

Input:

```text
graph_current/
query_index_invalidation/changed_graph_units.jsonl
dependency_map/graph_dependency_map.jsonl
```

Runner:

```text
tools/maintenance/graph_visual_review_incremental_refresher.py
```

Output:

```text
graph_v031_visual_review_incremental/
  graph_visual_review_index.html
  graph_visual_review_slices.jsonl
  graph_visual_review_incremental_manifest.json
  slices/*.json
  slices/*.graphml
```

Meaning:

Only affected bounded neighborhoods are refreshed. If there are no changed
graph units, a no-change manifest and HTML marker are still written.

## Acceptance Checks

The smoke package passes only if:

- S1 current view has active reviewed rows.
- S1 current view has historical/stale excluded rows.
- S2 current view has active reviewed rows.
- S2 current view has historical/stale excluded rows.
- graph publish detects nonzero changed graph units.
- incremental visual review writes nonzero affected slices.
- graph query default is ready through `graph_current/`.
- no durable memory write is executed.
- no graph truth write is executed.

## Boundaries

v0.4 first closure does not include:

- physical hard delete;
- silent in-place JSONL mutation;
- automatic entity merge;
- S3 / final support checker;
- permanent graph database backend;
- automatic full query-index rebuild;
- live provider calls inside the smoke package.
