## 关键发现

`.env` 中原配置的 `gpt-5.4-mini` 在当前 provider/group 下不可用，最小 curl 探针返回：

```text
model_not_found: No available channel for model gpt-5.4-mini under group Claude (distributor)
```

随后用用户此前确认过的 `claude-haiku-4-5` 做最小探针，返回成功：

```text
content: ok
HTTP_STATUS: 200
```

本轮没有修改 `.env`，只在 smoke 命令进程内临时覆盖：

```powershell
$env:OPENAI_MODEL_WEAK='claude-haiku-4-5'
$env:OPENAI_MODEL_STRONG='claude-haiku-4-5'
$env:OPENAI_API_MODE='chat_completions'
```

## 期间修复

发现 `build-full` 经由 S1/S2 runner 调用 prebuild routing 时，`api_mode` 默认固定为 `responses`，没有读取 `OPENAI_API_MODE`。

已修复：

- `tools/prebuild_routing.py`
- 当未显式传入 `api_mode` 时，读取 `OPENAI_API_MODE`，再回退到 `responses`
- CLI `--api-mode` 默认值从 `responses` 改为 `None`

这是 provider 配置生效修复，不改变 workflow 边界。
