# v0.41 Provider Profile / Fallback 配置说明

状态：已实现，默认不自动调用真实 provider。

## 目标

允许同一套 workflow 配置两个 OpenAI-compatible provider profile。
当前项目默认策略改为便宜 provider 优先：

```text
claude_secondary -> 默认先尝试
openai_primary   -> 只作为可选 fallback/占位
```

这解决的是 provider 可用性和冗余问题，不是模型质量投票系统。

## 配置入口

`.env.example` 已加入占位配置：

```env
PSML_PROVIDER_DEFAULT=claude_secondary
PSML_PROVIDER_FALLBACK=

PSML_PROVIDER_OPENAI_PRIMARY_API_KEY_ENV=OPENAI_API_KEY
PSML_PROVIDER_OPENAI_PRIMARY_BASE_URL=https://api.openai.com/v1
PSML_PROVIDER_OPENAI_PRIMARY_API_MODE=responses
PSML_PROVIDER_OPENAI_PRIMARY_WEAK_MODEL=
PSML_PROVIDER_OPENAI_PRIMARY_STRONG_MODEL=

PSML_PROVIDER_CLAUDE_SECONDARY_API_KEY_ENV=CLAUDE_COMPAT_API_KEY
PSML_PROVIDER_CLAUDE_SECONDARY_BASE_URL=
PSML_PROVIDER_CLAUDE_SECONDARY_API_MODE=chat_completions
PSML_PROVIDER_CLAUDE_SECONDARY_WEAK_MODEL=claude-haiku-4-5
PSML_PROVIDER_CLAUDE_SECONDARY_STRONG_MODEL=claude-haiku-4-5
```

真实 key 不写入仓库。可以直接写 `*_API_KEY`，也可以推荐使用 `*_API_KEY_ENV` 指向本机环境变量。

## Fallback 边界

会 fallback：

- `model_not_found`;
- retryable HTTP：408 / 409 / 429 / 5xx;
- timeout;
- transport failure;
- provider channel unavailable。

不会 fallback：

- JSON schema validation 失败；
- quote / evidence / backpointer validation 失败；
- 模型输出质量差；
- 候选关系抽取不合理；
- support checker 或 graph metric 分歧。

原因：fallback 只能处理 provider/service 可用性，不能把质量问题伪装成“换个模型就过了”。

## Manifest 记录

相关 runner 会记录：

```json
{
  "provider_profile_id": "claude_secondary",
  "provider_fallback_profile_id": null,
  "provider_fallback_enabled": false,
  "fallback_used_count": 0,
  "api_key_recorded": false
}
```

单条 provider 输出还会记录：

```json
{
  "provider_profile_id": "claude_secondary",
  "fallback_used": true,
  "fallback_reason": "RuntimeError: provider/service failure",
  "fallback_from_profile_id": "openai_primary"
}
```

## 当前边界

- 不修改真实 `.env`。
- 不提交真实 provider URL / key。
- 不自动 live API；仍需要 `--allow-live-api` 或 `ALLOW_LIVE_API=true`。
- `mock` 仍只用于测试和 baseline，不作为 live provider fallback。
