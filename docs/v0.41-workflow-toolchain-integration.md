# v0.41 Workflow + Toolchain 集成说明

日期：2026-05-30

状态：usable-alpha 薄编排入口。

## 定位

v0.41 不新增新的记忆语义层，也不重写 S1/S2/graph/v0.4 runner。

本轮只做一件事：

```text
把已有 workflow 和 tools 收束到一个统一入口
```

统一入口：

```powershell
python -m tools.workflow_runner ...
```

它负责：

- 调用现有 runner；
- 发现 workspace 里已有资产；
- 写 workflow-level manifest/report；
- 保留原有边界；
- 避免每次都在多份参考文档里拼命令。

## Agent 操作路由

Agent 接手项目任务时，不应该先猜应该调用哪个底层 runner。

默认顺序是：

```text
1. 先读本文件
2. 先跑 workflow status
3. 根据状态路由到已有 workflow/reference
4. 只有调试单步时才直接调用底层 runner
```

### 入口判断

Agent 收到任务后，先执行：

```powershell
python -m tools.workflow_runner status `
  --workspace users\<workspace_id>
```

然后按任务类型路由：

| 任务 | 首选入口 | 底层 reference |
| --- | --- | --- |
| 检查 workspace 到哪一步 | `tools.workflow_runner status` | 本文件 |
| 从 S0B/S1/S2 全量构建 | `tools.workflow_runner build-full` | `docs/references/step1-build/`, `docs/references/step1-index/`, `docs/references/step2-build/` |
| 构建候选图 / 图算法 / 图审计 | `tools.workflow_runner build-graph` | `docs/references/graph/v0.3-graph-toolchain-usage.md` |
| 查询 / 回答包 / 图融合检索 | `tools.workflow_runner query` | `docs/references/step2-query/10-fixed-query-runner.md` |
| 增量维护 / 人工审核 / current view | `tools.workflow_runner incremental` | `docs/v0.4-incremental-maintenance-workflow.md` |

### Agent 必须停下来的情况

以下情况不要继续自动推进：

- `incremental prepare` 已生成人工审核包，但 reviewer 尚未提交 `review_session_manifest.json`；
- 用户没有授权 live provider，而下一步需要 `--allow-live-api`；
- 缺少 workspace、source、target participant 等无法从 manifest 推断的关键输入；
- runner 报告缺 evidence/backpointer、graph truth boundary violation、或 unresolved endpoint hard blocker；
- 任务会写 durable memory、graph truth、S3 或外部服务状态。

### Agent 不该做的事

- 不要绕过 `tools.workflow_runner` 直接拼一长串旧命令，除非是在调试单步 runner。
- 不要把 mock/regex graph extraction 当成主 fidelity path。
- 不要把 `graph_current/`、NetworkX 指标、community report、visualization 当成证明。
- 不要把 current view、`graph_current/` 发布结果或 visualization 解释成 graph truth；它们只是派生视图 / 审查辅助，不是 canonical truth layer。
- 不要把 current view 发布解释成 canonical history rewrite。
- 不要在没有用户明确授权时打开 live provider。

## 总入口

### 1. 查看 workspace 状态

```powershell
python -m tools.workflow_runner status `
  --workspace users\<workspace_id>
```

输出：

```text
users/<workspace_id>/workflow_runs/<run_id>/
  workflow_manifest.json
  workflow_report.md
```

它会检查：

- S0B raw organization；
- S1 evidence / memory；
- S1 Index；
- S2 portrait / reviewed units；
- S2 Index；
- v0.3 graph construction / route / consolidation；
- `graph_current/`；
- v0.4 latest views。

### 2. 全量 S1/S2 build/index

```powershell
python -m tools.workflow_runner build-full `
  --workspace users\<workspace_id> `
  --modeled-user-id <user_id> `
  --target-participant <user_id>
```

默认策略：

- `proposal-provider=mock`；
- 不自动调用 live provider；
- S1 index 默认 lexical，避免误触发本地 embedding 环境约束。

真实 provider 需要显式开启：

```powershell
python -m tools.workflow_runner build-full `
  --workspace users\<workspace_id> `
  --modeled-user-id <user_id> `
  --target-participant <user_id> `
  --proposal-provider openai `
  --allow-live-api `
  --provider-concurrency 4
```

如果要跑本地 embedding，应显式指定原 runner 支持的参数，并使用已配置的环境。

### 3. 构建 v0.3 graph 工具链

mock / baseline smoke：

```powershell
python -m tools.workflow_runner build-graph `
  --workspace users\<workspace_id> `
  --provider mock_regex_baseline `
  --max-items 20 `
  --duplicate-policy overwrite_generated
```

真实 provider：

```powershell
python -m tools.workflow_runner build-graph `
  --workspace users\<workspace_id> `
  --provider openai `
  --allow-live-api `
  --provider-concurrency 8 `
  --max-items 80 `
  --duplicate-policy overwrite_generated
```

可选可视化：

```powershell
python -m tools.workflow_runner build-graph `
  --workspace users\<workspace_id> `
  --provider mock_regex_baseline `
  --visual `
  --duplicate-policy overwrite_generated
```

内部顺序：

```text
graph construction packets
  -> route_graph_extraction
  -> provider/mock extraction
  -> candidate consolidation
  -> NetworkX utility
  -> profile/community
  -> final quality gate
  -> optional visual review bundle
```

边界：

- mock/regex 仍只是 baseline，不是主 fidelity path；
- graph rows 仍是 candidate material；
- graph metrics / communities / visualization 不是 support proof。

### 4. 查询

```powershell
python -m tools.workflow_runner query `
  --workspace users\<workspace_id> `
  --question "Lucilla 和 the Doctor 是什么关系？"
```

查询入口会优先发现：

```text
graph_current/
```

如果没有，再回退到：

```text
graph_v03_consolidation_provider_80/
graph_v03_consolidation/
```

实际用户查询仍由：

```text
tools.step2.query_runner
```

执行。统一入口只负责自动补齐 graph context 参数和写 workflow manifest。

查询路径仍是三路融合：

```text
Step 1 evidence retrieval
Step 2 lexical / BM25 retrieval
Step 2 embedding retrieval
v0.3 graph-aware retrieval
```

默认 prompt view 仍保持轻量；证据链和路径主要用于 why/audit/review 场景。

### 5. v0.4 增量维护

准备人工审核包：

```powershell
python -m tools.workflow_runner incremental `
  --workspace users\<workspace_id> `
  prepare `
  --reset `
  --port 8765
```

审核完成后 finalize：

```powershell
python -m tools.workflow_runner incremental `
  --workspace users\<workspace_id> `
  finalize
```

快速 smoke：

```powershell
python -m tools.workflow_runner incremental `
  --workspace users\_v04_incremental_workflow_smoke_manual `
  smoke `
  --reset
```

human review gate 不会被跳过。正常 `prepare` 之后必须由 reviewer 提交：

```text
human_review/review_decisions.jsonl
human_review/review_session_manifest.json
```

否则 `finalize` 必须失败。

## 输出结构

每次运行统一写：

```text
workflow_runs/<run_id>/
  workflow_manifest.json
  workflow_report.md
```

manifest 至少记录：

- workflow command；
- run id；
- workspace；
- step list；
- step outputs；
- source hashes / discovered graph context；
- boundary flags。

固定边界：

```text
durable_memory_written=false
graph_truth_written=false
support_checker_authority=false
s3_written=false
```

## 不做什么

v0.41 不做：

- 重写 S1/S2/graph/v0.4 runner；
- 改 query ranking；
- 改 graph extraction prompt；
- 自动 live provider；
- 自动 durable memory write；
- 自动 graph truth write；
- 自动 S3/support checker；
- 自动安装外部图数据库或外部资源。

一句话：v0.41 是把已经能跑的骨架变成一个能找得到、跑得动、看得懂的入口。
